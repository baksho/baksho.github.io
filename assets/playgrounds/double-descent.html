Double Descent Playground

Fit noisy data with a model made of p random features and let p grow. Classical statistics says error should rise once the model is too flexible. Here it rises, spikes when the model has exactly as many features as there are data points (p = n), and then falls again. Press play to sweep the model size and watch the test error. The Settings panel on the right changes the data (n, noise, true function) and the model (roughness, ridge penalty).

How it works

What this page is, and is not. It is a small, controlled toy: one input, random smooth features and a fit computed exactly. It shows the double descent shape clearly. It does not show that deep networks behave the same way, which is an empirical finding studied in the papers below.

The model

There are n training points (x, y) with y = f(x) + noise. The model has p random features φ1(x), …, φp(x) and predicts f̂(x) = Σ cj φj(x) / √p. Each feature is a random smooth function: a random combination of 160 cosine waves whose weights shrink with frequency as (1 + k)−γ. The features are fixed once drawn; only the coefficients c are fitted. Model size means the number of features p. The features are nested, so going from p to p + 1 adds one new feature and keeps the others.

The fit

For p < n the fit is ordinary least squares. For p ≥ n there are many coefficient vectors that pass exactly through every training point, and the fit picks the one with the smallest ‖c‖ (the minimum-norm solution). With ridge penalty λ > 0 it minimises the squared error plus λ‖c‖² instead. It is computed through the n × n kernel matrix, with a tiny numerical safeguard (a relative ridge of 1e-10) when λ is 0.

The three regimes

  • p well below n. The model is too small to fit every point. As p grows, the fit improves but also starts to follow the noise, which is the classical U-shape.
  • p near n. Exactly enough features to hit every noisy label. The system is close to singular, so the coefficients must become very large to do it (see the second chart), and the fit swings wildly between the data points. This is the spike.
  • p well above n. Many exact fits exist, and the minimum-norm one is far better behaved than the one at p = n. The error falls again.

What to try

  • Drag the training points n slider in Settings (it restarts the sweep) and watch the spike move with it. In 20-trial runs I measured the median test error peaking exactly at p = 15, 30 and 50 for n = 15, 30 and 50.
  • Set the noise to 0. The spike shrinks a lot but does not vanish, because the true function cannot be represented exactly by the features. In my 20-trial run at n = 30 the median at p = n went from about 1100 at σ = 0.3 to about 10 at σ = 0.
  • Raise the ridge penalty. With λ = 0.01 the large spike disappears in my 20-trial run; a small, gentle bump in the median remains a little below p = n, and the error then settles lower than at the start.
  • Compare median and mean. Near p = n a few random draws are catastrophic, so the mean is dominated by them while the median stays readable. Individual trials differ a lot, which the faint lines show.

A note on how I built it

I first tried the textbook version, random Fourier features of a single input. In one dimension these features are so smooth and so similar to one another that the system is badly conditioned for the whole range of p, and the results were dominated by numerical noise rather than a clean peak at p = n. The random functions used here keep the features varied enough that the peak lands exactly at p = n. The roughness slider shows the trade-off: smoother features make the fit more fragile.

Limits

Values like "peak at p = n" are measured here for this feature family. In other settings (different features, higher-dimensional inputs, trained networks) the peak position and size can differ. The analytic results in the literature are for specific high-dimensional random-feature models, not this one-input toy.
