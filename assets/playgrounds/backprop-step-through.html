Backprop Step-through

A neural network is a long chain of small operations. Backpropagation computes how the final loss changes when each input or weight changes, by walking the chain backwards and applying the chain rule one node at a time. Here the chain is tiny, so you can follow every number. Step forward to compute the values, then step backward to compute the gradients. Pick the graph and change its input values in the Settings panel on the right.

How it works

What this page is. A scalar toy: every node holds one number. Real networks apply the same two passes to large arrays of numbers (tensors), but the logic at each node is the one you see here.

The graph

Each box is a node. The boxes on the left with no incoming arrows are the leaves: inputs, weights, biases and targets. Every other box applies one simple operation (add, multiply, sigmoid, square, ...) to the nodes that point into it. The last node is the output, here a loss or a function value. Each box shows its name, the formula that defines it, its value (blue), and once the backward pass has reached it, its gradient (orange).

Forward pass

Starting from the leaves, compute each node from the nodes before it, in order. Nothing is differentiated yet. The values are kept, because the backward pass needs them.

Backward pass

The question is: if this node changed by a tiny amount, how much would the output change? That ratio is the node's gradient, written ∂out/∂node. It starts at the output, where ∂out/∂out = 1. Then the nodes are visited in reverse order. At a node n with input u, two numbers are combined:

  • the upstream gradient ∂out/∂n, already known because every node after n has been handled;
  • the local derivative ∂n/∂u, which depends only on that one operation and the values saved in the forward pass.

The chain rule says to multiply them:

∂out/∂u  +=  (∂out/∂n) · (∂n/∂u)

The orange box in the explanation panel spells this out with the actual numbers at every step.

Why gradients are added

If a node is used by more than one later node, a change in it reaches the output along more than one path, and the effects add. That is the "+=" above. The graph "One input used twice" shows it: x feeds both x·y and sin(x), so its gradient is a sum of two contributions, which you can watch arrive in two separate steps.

Why backwards

A node's gradient is only final after every node that uses it has been processed. Walking the graph in reverse order guarantees that, and it gives the gradient of the output with respect to every leaf in one sweep, instead of one separate computation per leaf.

The gradient check

When the backward pass finishes, the panel on the right compares each leaf gradient with a numerical estimate: nudge the leaf by ±10−5, rerun the whole forward pass, and take (output(+) − output(−)) / (2·10−5). The two should agree to many digits. This check is the standard way to test a hand-written backward pass. In my tests the two agreed to about 10−10 (relative) on 1,800 randomly drawn leaf gradients across the three graphs.

Limits

This shows reverse-mode differentiation on a fixed, tiny graph. It does not show how a network is trained (that needs many examples and an update rule such as gradient descent), nor how frameworks organise the computation on tensors and hardware.
