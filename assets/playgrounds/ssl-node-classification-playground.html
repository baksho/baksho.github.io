Semi-supervised Node Classification Lab

Only a handful of nodes in this graph have a known class. A two-layer graph convolutional network (GCN) is trained on those few labels, and it predicts the class of all the other nodes by mixing each node's features with its neighbours'. Press Play to watch the predictions form, click a node to label or unlabel it, and compare with a model that ignores the graph (an MLP) and with label propagation, which uses only the graph and the labels. The graph comes from a stochastic block model with a homophily slider (how often an edge joins two nodes of the same class), or from the real Zachary Karate Club. Slide homophily down and watch the graph stop helping, and then start hurting.

How it works

In semi-supervised node classification you are given a graph and the input features of every node, but the class of only a few nodes. The task is to predict the classes of all the others. Everything below is computed in your browser, and the training is deterministic, so the Epoch slider simply moves through a training run that has already been computed.

The data

  • Graph. A stochastic block model (Holland, Laskey and Leinhardt, 1983): the nodes are split into K classes of equal size, and every pair of nodes is connected independently, with a higher probability inside a class than between classes. The page sets the probabilities from two numbers: the mean degree and the edge homophily h, the expected fraction of edges that join two nodes of the same class. For K classes, random wiring gives h = 1/K (0.5 for two classes). The randomness is coupled: for a fixed seed, raising h only adds within-class edges and removes between-class edges, so the graph changes smoothly as you drag the slider. I checked that the realised mean degree and the realised homophily match their targets (300 graphs per setting; for instance target h = 0.8 gave 0.796).
  • Features. Ten numbers per node: the node's class adds a shift of size "feature signal" along one axis of its own, and every one of the ten numbers has unit Gaussian noise. Most of the dimensions carry no class information, so a model with a few labels can easily overfit to noise.
  • Labels. A few nodes per class, chosen at random (or by you, by clicking). Test accuracy is always measured on all nodes without a label. Test labels are never used for training, model selection or early stopping.
  • Karate Club. The real Zachary Karate Club network (Zachary, 1977): 34 members, 78 ties, two factions of 17. The data has no node features, so the page simulates them in the same way as for the block model. About 86% of the ties join members of the same faction.

The three methods

GCN: P = softmax( Â · ReLU( Â X W₁ ) · W₂ ), Â = D̃−½(A + I)D̃−½
MLP: the same, with Â = I (graph structure off)
LP: F ← α S F + (1 − α) Y, S = D−½ A D−½, α = 0.9

The GCN is the two-layer model of Kipf and Welling (2017), without bias terms. The hidden layer has 16 units. Training minimises the cross-entropy on the labelled nodes with Adam (learning rate 0.01, full batch) for 200 epochs, plus weight decay on both weight matrices (5e-4 unless you change it). There is no dropout, so the run is deterministic. The MLP is exactly the same network and the same initial weights with Â replaced by the identity, so the only difference between the two is whether a node can see its neighbours. Label propagation (Zhou et al., 2003) uses no features at all: the known labels are pushed along the edges for 200 steps, and every node gets the class with the largest score. A node that no label can reach gets no prediction and counts as wrong.

I checked the implementation against an independent numpy version that rebuilds Â from the edge list and runs its own Adam: the training-loss trajectories of four GCN and MLP runs agree to 4e-16 over 120 epochs. The analytic gradient agrees with finite differences (largest relative error 3e-7), and label propagation after 300 steps matches its closed form (1 − α)(I − αS)−1Y to 1e-16.

What the page shows

All numbers in this section are means over 40 random graphs with the default settings (60 nodes, mean degree 4, feature signal 1, 3 labelled nodes per class, test accuracy after 200 epochs, standard error about 0.01 to 0.02), not the single graph you see on screen. The sweep chart on the page recomputes the same kind of curve with 8 graphs per point for whatever settings you choose.

  • Two classes. The MLP, which ignores the graph, scores 0.60 at every h (the features and labels do not depend on h). GCN scores 0.95 at h = 1, 0.88 at 0.9, 0.78 at 0.8 and 0.68 at 0.7. At h = 0.6 it is level with the MLP (0.58). It then drops below the MLP: 0.52 at h = 0.5, a minimum of about 0.50 near h = 0.3 to 0.4, and 0.54 at h = 0.2. At h = 0.1 it is level again (0.60), and at h = 0, where every edge joins the two classes, it rises to 0.71. Label propagation follows the homophilous end (0.98 at h = 1, 0.74 at 0.8) but never learns from heterophily: 0.46 at h = 0.
  • Three classes. The MLP scores 0.44. GCN is below it for h from 0 to 0.4 (0.34, 0.32, 0.34, 0.37 at h = 0, 0.1, 0.2, 0.3; 0.42 at 0.4), above it from h = 0.5 (0.48) and at 0.82 for h = 0.8. There is no recovery at low h this time.
  • Feature signal. With a weak signal (0.5) the graph helps at h = 0.8 (GCN 0.70 against 0.52). With a strong signal (3) the MLP already scores 0.89, GCN is level with it at h = 0.8 (0.90), and at h = 0.5 GCN is far worse (0.63).
  • Number of labels. At h = 0.8 with two classes, GCN scores 0.70, 0.75, 0.78, 0.80, 0.82 for 1, 2, 3, 5, 10 labels per class, and the MLP 0.56, 0.60, 0.60, 0.63, 0.64. The graph helps most when labels are scarce: with one label per class label propagation (0.66) is already well ahead of the MLP.
  • Mean degree. At h = 0.8, GCN scores 0.68, 0.78 and 0.91 for mean degree 2, 4 and 8. At h = 0.5, degree 8 gives 0.54, still below the MLP (0.60).
  • Karate Club. With simulated features of signal 1 and 60 random draws of features and labelled nodes, GCN scores 0.88, 0.90 and 0.91 for 1, 2 and 3 labelled members per faction. The MLP scores 0.55, 0.55 and 0.59, label propagation 0.80, 0.89 and 0.92.

Why the graph can hurt

One step of GCN averages a node with its neighbours. Take the simple mean version with a self-loop, mean degree d, K classes with equal means separated along their own axes, and unit noise. Averaging 1 + d independent noise terms shrinks the noise standard deviation by √(1 + d). The class signal changes too: the node keeps a share 1/(1 + d) of its own mean, and each neighbour contributes its own class mean, which belongs to the node's class with probability h and to each other class with probability (1 − h)/(K − 1). The class means of two nodes of different classes end up separated by a factor (1 + d·(h − (1 − h)/(K − 1)))/(1 + d) of what they were. Taking the ratio of the signal factor to the noise factor gives a signal-to-noise gain:

gain(h) = ( 1 + d · ( h − (1 − h)/(K − 1) ) ) / √(1 + d)

The graph can only help where |gain| > 1. Two classes make a distinctive case: for K = 2 the factor is 1 + d(2h − 1), which is negative for small h but large in size when h is near 0. The sign does not matter to a classifier that can learn the sign, so strong heterophily is as useful as strong homophily. In the middle, the signal cancels (h = 0.5 − 1/(2d) for K = 2) and only the noise reduction is left. With d = 4 the formula gives |gain| < 1, that is, a graph that hurts, for h between 0.10 and 0.65 when K = 2. The measured curve is below the MLP over about the same range (equal at 0.1 and at 0.6). For K = 3 it gives |gain| < 1 for every h up to 0.54, and no recovery at low h, because the minimum of the gain is −0.45: a neighbour of another class does not say which class you are. The measured GCN is below the MLP up to about 0.4 and above it from 0.5, so the formula is slightly pessimistic. You can draw the gain on the sweep chart with the last checkbox in Settings.

I also measured the gain directly on 900-node graphs, using the GCN normalisation: signal-to-noise of the propagated features relative to the raw features. For K = 2 and d = 4 it was 2.11 at h = 1 (formula 2.24), 1.48 at h = 0.8 (1.52) and 0.82 at h = 0.6 (0.81). Near the cancellation point it is off: the formula gives 0.09 at h = 0.4 and I measured 0.22, because node degrees vary (a node's cancellation point depends on its own degree) and the formula uses the mean degree. For K = 3 the values at h = 0.6, 0.8 and 1 were 1.16, 1.64 and 2.09 (formula 1.16, 1.70, 2.24). This is a back-of-the-envelope model for one averaging step with a linear classifier. It ignores the second layer, the training from a handful of labels, and the normalisation by degree.

This agrees with what the literature says about heterophily. Zhu et al. (2020) report that many popular GNNs fail on networks with heterophily and are even outperformed by models that ignore the graph, such as MLPs. Ma et al. (2022) show that this is not quite the full story: GCNs can achieve strong performance on some heterophilous graphs ("good" heterophily), which is the two-class h = 0 case here. Li, Han and Wu (2018) describe the GCN convolution as a form of Laplacian smoothing, which is the averaging the model above relies on.

Limits of this page. The graphs have 20 to 150 nodes and the features are Gaussian, so the numbers show the mechanism, not the accuracy of GCN on real data sets. Heterophily here is the simplest kind: the between-class edges are spread evenly over all other classes. Real heterophilous graphs can be structured differently, and then the picture changes (that is the point of Ma et al., 2022). I used one training recipe (hidden size 16, learning rate 0.01, 200 epochs, no dropout, no early stopping, no hyper-parameter search); a tuned model may do better on the same data. A single graph on the screen is a small sample: with 54 test nodes, one node is worth 1.9 percentage points, and a single run can differ from the mean by more than 10 points. Use the sweep chart for the typical behaviour. Label propagation here is the plain version with α = 0.9 and counts unreachable nodes as wrong; in sparse graphs some nodes have no path to any label.

Things to try

  • Pick "Random edges", press To end, and compare GCN with the MLP. Then switch the model to MLP: the graph structure is off and accuracy goes up.
  • Drag the homophily slider from 1 down to 0 with two classes and watch the navy dot on the sweep chart follow the U-shaped curve.
  • Switch to three classes at h = 0.2 and check that the U-shape is gone.
  • Set the feature signal to 0: the features say nothing about the class, so the MLP and GCN have nothing to learn from, while label propagation, which uses no features, is unaffected.
  • Click an unlabelled node to label it and see how the predictions change. Choose "Accuracy by hops to a label" to see where the graph methods fail.
